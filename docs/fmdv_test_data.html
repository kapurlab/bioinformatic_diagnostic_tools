vSNP3 · FMDV mode

Test data for a new FMDV project

Every sample here is public. Paste the accession numbers into vSNP3 and it downloads them for you — nothing is handled by hand. Each one has a known answer, printed beside it, so you can tell whether your install is working.

Before you start

FMDV mode needs its reference library built once on the machine. With the machine online, in the tools folder:

bin/bdtools setup-databases fmdv

It takes about five minutes and ends with FMDV reference library ready. Then click ↻ Restart on the vSNP3 card so it finds the library. If the command says the environment lacks blastn, run bin/bdtools update vsnp_gui first and try again.

Make the project first In Projects, type a name (for example FMDV_test), choose FMDV mode (reference chosen per sample) in the list beside it, then Create. Click the new card to open it. Without FMDV mode the reference is fixed for the whole project, which is wrong for FMDV.

The starter set — four samples, four ways in

These four are the set the release was tested with. They are deliberately mixed: nanopore reads, Illumina reads, and two finished genomes from GenBank, so one run exercises every way into the tool.

How to bring them in

  1. The two read sets. In Inputs, click the SRA tab. Paste the two SRA numbers, one per line, and click Download. It takes under a minute on a good connection and ends with 2 downloaded.
  2. The two genomes. Click the Sequences tab. Paste the two GenBank numbers and click Preview. Each row should say genome with its length, and VP1 located inside it. Click Import 2 records.
    A genome becomes reads vSNP3 writes perfect paired reads from the sequence so it can go through Step 1 like any sample. The depth is 100× by default, and the Read depth box beside the preview changes it. The sample is badged Simulated everywhere afterwards and its quality check reads N/A, because depth and coverage would only describe the simulation.
  3. A file instead of an accession. A FASTA or GenBank file from a colleague works the same way: drop it on the same tab, or use Choose Files, then Preview. You can change the name before importing.
    Not only FMDV Since v0.4.155 the Sequences tab is in every project. A published genome or an assembly can be imported into a TB, Brucella or any other project the same way, and it joins Step 2 beside your own samples. Outside FMDV mode nothing is typed: the record is simply a sample with reads.
  4. Run them. Grab into Step 1, then in Step 1 leave the three scope lists on Auto and click Run. Four samples take about a minute. Do not tick Nanopore (ONT) reads — long reads are detected per sample.
  5. Read the answer. In Step 1 Results click Refresh, then compare with the table below.

The one to look at SRR34371563 is 100% identical on VP1 to MT602086.1 — the published genome of the same isolate, TAN/27/2012. The reads came out of the archive and the genome came out of GenBank by two different routes, and the tool put them on top of each other. That is the check that matters.

Then the trees and the SNP table

  1. In Step 2, on the VP1 tab, choose SAT1 (2 samples) and click Build VP1 tree (about 4 minutes). Then do the same for O (2 samples) — that tree is larger, up to 15 minutes.
  2. In Step 2 Results, the Neighbours view should put EU448369 among United Kingdom records from 1967 and 1968, its nearest at 100%.
  3. On the Genome SNPs: build tab, choose SAT1-I_KM268899 (2 samples), click Build comparison set, then Run. The two O samples are on other references and are left out, as the panel says.

With this reference's databases built (see docs/FMDV_MODE.md in the vsnp_gui repository, “Step 2 context”), that comparison is 49 sequences over 2,729 positions, and SRR34371563 comes out 0 SNPs from MT602086.1 and 6 from the reference, with the next genome more than 380 away. Without them the table holds your two samples only, and the steps are the same.

The full set — Pirbright's twelve runs

For a harder test, BioProject PRJNA693428 holds twelve runs over six biological samples: serotypes A, O and Asia1 from cell culture (CC), epithelium (EPI) and oral swab (OS). These behave like field samples — their reads sit 15% or more from the nearest library genome, only 15 to 55% of the reads are FMDV at all, and there is 1 to 5% crosstalk between barcodes.

Paste them into the SRA tab the same way. The nine MinION runs are 6.7 GB and take a while to download; the three MiSeq runs are small and serve as an independent check of the reference chooser on three of the same biological samples.

Two of these runs are the same data SRR13498122 (labelled A) and SRR13498123 (labelled O) report exactly the same read count, the same base count, and the same hashes in the SRA run table. That is visible in the metadata before anything is downloaded. Whatever the tool says about those two, do not read a match between them as evidence of anything.
The labels are not the answer The library names carry the submitter's serotype. They are metadata, not evidence. Keep them to one side and compare them with the call the pipeline makes — that comparison is the test.

If something goes wrong

What you seeWhat to do
The reference list has no FMDV mode choicevSNP3 is older than v0.4.154. Run bin/bdtools update vsnp_gui, then ↻ Restart.
Step 1 says FMDV reference library not foundRun bin/bdtools setup-databases fmdv, then ↻ Restart and reload the page.
The Inputs panel has no Sequences tabvSNP3 predates v0.4.155, where that tab was FMDV-only. Run bin/bdtools update vsnp_gui, then ↻ Restart.
The preview says NCBI is unreachableThe machine is offline. Download the record elsewhere (Send to → File → GenBank full) and drop that file on the same tab.
A download says Failed for some accessionsPaste the whole list again and click Download. Only the missing ones are fetched.
A sample says Error in Step 1Click View log beside it. To try again, tick Force re-run and Run.
Anything elseIn the tools folder, bin/bdtools doctor vsnp_gui lists what is wrong and the command that fixes it.
