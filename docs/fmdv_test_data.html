vSNP3 · FMDV mode

Test data for a new FMDV project

Every sample here is public. Paste the accession numbers into vSNP3 and it downloads them for you — nothing is handled by hand. Each one has a known answer, printed beside it, so you can tell whether your install is working.

Before you start

FMDV mode needs its reference library built once on the machine. With the machine online, in the tools folder:

bin/bdtools setup-databases fmdv

It takes about five minutes and ends with FMDV reference library ready. Then click ↻ Restart on the vSNP3 card so it finds the library.

If BLAST+ is missing FMDV mode needs two programs in vSNP3's environment that an install made before v0.4.154 does not have: BLAST+ (blastn) and mafft. Without blastn the command above stops, and the Sequences tab says Nothing can be imported yet. Add them with bin/bdtools update vsnp_gui on your own computer. On a shared install an administrator runs these two instead. The first brings the tools list up to date, which matters: before 19 November 2026 the second one skipped a missing program and said there was nothing to install.
bin/bdtools pull
bin/bdtools update-packages vsnp_gui
It should list blast none -> 2.17.0, mafft none -> 7.526 and sra-tools none -> 3.4.1, then install them. Nothing needs restarting for the Sequences tab: click Preview again.
Make the project first In Projects, type a name (for example FMDV_test), choose FMDV mode (reference chosen per sample) in the list beside it, then Create. Click the new card to open it. Without FMDV mode the reference is fixed for the whole project, which is wrong for FMDV.

How to bring them in

  1. The two read sets. In Inputs, click the SRA tab. Paste the two SRA numbers, one per line, and click Download. It takes under a minute on a good connection and ends with 2 downloaded.
    While it downloads A counter beside Downloading… runs from the moment you clicked. A file still arriving is kept out of Ready to run until it is whole, so the list fills one sample at a time. Since v0.4.156 a transfer that stops moving is picked up again from where it stopped, with no action from you, and Stop ends the download; pressing Download again carries on with whatever is missing. On a machine without sra-tools the reads come from the European archive (ENA) instead of NCBI, which can be several times slower.
  2. The two genomes. Click the Sequences tab. Paste the two GenBank numbers and click Preview. Each row should say genome with its length, and VP1 located inside it. Click Import 2 records.
    A genome becomes reads vSNP3 writes perfect paired reads from the sequence so it can go through Step 1 like any sample. The depth is 100× by default, and the Read depth box beside the preview changes it. The sample is badged Simulated everywhere afterwards and its quality check reads N/A, because depth and coverage would only describe the simulation.
  3. A file instead of an accession. A FASTA or GenBank file from a colleague works the same way: drop it on the same tab, or use Choose Files, then Preview. You can change the name before importing.
    Not only FMDV Since v0.4.155 the Sequences tab is in every project. A published genome or an assembly can be imported into a TB, Brucella or any other project the same way, and it joins Step 2 beside your own samples. Outside FMDV mode nothing is typed: the record is simply a sample with reads.
  4. Run them. Grab into Step 1, then in Step 1 leave the three scope lists on Auto and click Run. Four samples take about a minute. Do not tick Nanopore (ONT) reads — long reads are detected per sample.
  5. Read the answer. In Step 1 Results click Refresh, then compare with the table below.

Then the trees and the SNP table

  1. In Step 2, on the VP1 tab, choose SAT1 (2 samples) and click Build VP1 tree (about 4 minutes). Then do the same for O (2 samples) — that tree is larger, up to 15 minutes.
  2. In Step 2 Results, the Neighbours view should put EU448369 among United Kingdom records from 1967 and 1968, its nearest at 100%.
  3. On the Genome SNPs: build tab, choose SAT1-I_KM268899 (2 samples), click Build comparison set, then Run. The two O samples are on other references and are left out, as the panel says.

With this reference's databases built (see docs/FMDV_MODE.md in the vsnp_gui repository, “Step 2 context”), that comparison is 49 sequences over 2,729 positions, and SRR34371563 comes out 0 SNPs from MT602086.1 and 6 from the reference, with the next genome more than 380 away. Without them the table holds your two samples only, and the steps are the same.

The full set — 77 samples, every serotype

The starter set proves the install. This one exercises the reference chooser and the typing across all seven serotypes — O, A, Asia1, C, SAT1, SAT2 and SAT3 — on 45 public read sets and 32 GenBank genomes. The 77 samples land on 34 different lineage references. It goes in through the same two tabs as the starter set, so nothing new has to be learned. Use a new FMDV project for it (for example FMDV_all_serotypes).

Where the samples come from Public read sets exist for O, A, Asia1, SAT1 and SAT2. The archives hold no run labelled serotype C, and the only SAT3 reads are from a mixed SAT1/2/3 experiment, so those two serotypes are covered by GenBank genomes only. None of the 32 genomes is one of the library's own 79 lineage genomes, so the chooser has to find the nearest one rather than itself.

Run it and read the result

  1. Grab into Step 1, leave the three scope lists on Auto, and click Run. The 77 samples took about nine minutes on a laptop.
  2. In Step 1 Results click Refresh. You should count O 18 · A 12 · Asia1 10 · C 6 · SAT1 15 · SAT2 9 · SAT3 7, and for the 45 read sets 30 PASS, 12 REVIEW, 3 FAIL.
  3. In Step 2, the VP1 tab now lists all seven serotypes with those counts. Build a tree for any of them, one serotype at a time, as in the starter set.
The score 74/77 samples are called as the serotype their own submitter recorded. The three that are not are the interesting ones, and the tool does not claim them: it reports them as untyped (see below). Beyond the serotype, every lineage a submitter named is the lineage the tool calls — CATHAY, Ind-2001a, Ind-2001b, Ind-2001c, Ind-2001d, Sea-97, Iran-05, Sindh-08 and SAT1 topotype X.
Results that are not a fault The REVIEW and FAIL verdicts are real. The Pirbright MiSeq runs are amplicons that do not span the whole genome, and several field runs are mostly host reads — SRR9335110 maps 4% of its reads, SRR17960074 14%. All of them are still typed correctly.
Three genomes are called as the wrong serotype, and the tool says it could not type them. PP432673 (SAT2, Türkiye) and PQ587566 (SAT2, Ethiopia) land on a SAT1 reference, and PX864600 (O, Ghana) on an A reference. All three are far from every genome in the library: about a quarter of their simulated reads do not map at all, only around 72% of the genome is called, and no read reaches VP1, so the VP1 column reads 0% and the sample is reported untyped. When a row says untyped, the serotype beside it is only the reference the reads landed on — it is not a call. That is what the edge of the library's reach looks like, and it is the reason to read the VP1 column rather than the reference name.
Four genomes read under 100% against their own record. AY593795, HQ631363, AY593847 and MH053340 are far enough from the library that part of VP1 is left uncalled; the serotype is right in every case.

The Pirbright set — twelve field-like runs

For a harder test, BioProject PRJNA693428 holds twelve runs over six biological samples: serotypes A, O and Asia1 from cell culture (CC), epithelium (EPI) and oral swab (OS). These behave like field samples — their reads sit 15% or more from the nearest library genome, only 15 to 55% of the reads are FMDV at all, and there is 1 to 5% crosstalk between barcodes.

Paste them into the SRA tab the same way. The nine MinION runs are 6.7 GB and take a while to download; the three MiSeq runs are small and serve as an independent check of the reference chooser on three of the same biological samples.

Two of these runs are the same data SRR13498122 (labelled A) and SRR13498123 (labelled O) report exactly the same read count, the same base count, and the same hashes in the SRA run table. That is visible in the metadata before anything is downloaded. Whatever the tool says about those two, do not read a match between them as evidence of anything.
The labels are not the answer The library names carry the submitter's serotype. They are metadata, not evidence. Keep them to one side and compare them with the call the pipeline makes — that comparison is the test.
